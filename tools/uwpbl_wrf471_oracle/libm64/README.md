# glibc 2.43 binary64 exp/log/pow on the device, and correctly rounded cos/acos

Proof harness for `woof/core/kernels/glibc_flt64.cuh`, the binary64 libm
the UW PBL port (bl_pbl_physics = 9) calls where WRF's gfortran build calls
glibc.

The device header is `woof/core/kernels/glibc_flt64.cuh`. No binary32 macros are redefined. NVRTC options are `-std=c++17`, with the project default `--fmad=true`. No `--device-int128` option is required. The two-limb replacement computes unsigned arithmetic modulo 2^128.

The host harness includes the exact device header through `host_shim.h`. The file keeps the requested `sweep_cpu.c` name and is compiled as C++17 to consume the header namespaces. Basic operations use inline shim functions and `-ffp-contract=off`. Explicit fused operations call `fma`. References for exp/log/pow are function pointers returned by `dlsym` on `libm.so.6`. No numpy transcendental ufunc is used.

Run on the oracle host (x86-64 with FMA and AVX2, the glibc build the
oracle links, here Ubuntu GLIBC 2.43), from a scratch directory holding the
header, `common.cuh`, `glibc_flt32.cuh`, this directory's files and
`upstream/`, with a CuPy environment for the GPU half:

```bash
export TMPDIR="$PWD"
export CUPY_CACHE_DIR="$PWD/cupy-cache"
gcc -O2 -ffp-contract=off -c upstream/cos.c upstream/acos.c
g++ -x c++ -std=c++17 -O2 -ffp-contract=off -fopenmp -c sweep_cpu.c -o sweep_cpu.o
g++ sweep_cpu.o cos.o acos.o -fopenmp -lm -ldl -o sweep_cpu
for f in exp log pow; do ./sweep_cpu "$f" 17179869184 16 > "cpu-$f.log"; done
for f in acos cos composite dense; do ./sweep_cpu "$f" 4294967296 16 > "cpu-$f.log"; done
for f in cosbits acosbits; do ./sweep_cpu "$f" 268435456 16 > "cpu-$f.log"; done
gcc -O2 -ffp-contract=off -fPIC -c upstream/cos.c -o cos.pic.o
gcc -O2 -ffp-contract=off -fPIC -c upstream/acos.c -o acos.pic.o
g++ -std=c++17 -O2 -ffp-contract=off -fopenmp -shared -fPIC reference_batch.cpp cos.pic.o acos.pic.o -lm -ldl -o reference_batch.so
python3 probe.py
python3 capture.py
python3 capture_identity.py
g++ -std=c++17 -O2 -ffp-contract=off -shared -fPIC table_identity.cpp -lm -o table_identity.so
python3 table_identity.py > table-identity.json
python sweep_gpu.py --count 268435456 > gpu-full.log
```

The GPU sweep ran on an RTX 4090 (NVRTC 13.4) on 2026-09-30.

Inputs use the deterministic SplitMix64 sequence in `sweep_cpu.c`. Each exp/log/pow stream mixes random binary64 bit patterns, scheme ranges, special values, subnormals, neighborhoods of exp overflow and underflow thresholds, log inputs near one, and negative pow bases with integer exponents. Pow also has 4096 directed threshold arguments and the requested fixed exponents plus random exponents in [-4,4]. GPU arguments are generated by this same C++ code in `reference_batch.cpp`, so numpy only owns buffers and compares uint64 bits.

`acos` uses uniform inputs in [-1,1]. `cos` uses uniform inputs in [-2.1,3.15]. `composite` compares glibc cos(glibc acos(x)/3) to uw_cos(uw_acos(x)/3), including the intermediate rounded division. `dense` sweeps six interleaved streams: descending representable values from +1 and -1, positive and negative subnormals from zero, and a fine arithmetic grid around zero. Endpoints are included. `cosbits` adds random finite binary64 inputs across the exponent range. `acosbits` adds random admissible binary64 bit patterns.

The `transcription_mismatches` field compares the pinned host adaptation to original CORE-MATH C compiled with `-O2 -ffp-contract=off`. It is zero in every trig stream. The upstream algorithm supplies the correctly rounded reference; MPFR was not needed. The first 20 mismatches, ordered by stream index, are preserved with uint64 hexadecimal arguments and outputs in each `cpu-*.log` file.

`FMA-SITES.md` maps every Arm FMA to the installed instructions. `probe.log` records live public addresses and resolved PLT targets. `table-identity.json` records byte comparison and SHA256 hashes of all three lookup tables. `host-environment.json` records the compiler, glibc, CPU features, and installed libm hash. `upstream-sha256.json` identifies each retained upstream source.

Mechanical generation uses `generate.py` with the Python libclang binding. It selects the active Arm configuration and wraps every floating arithmetic AST node. Copy `generated.inc` back into this directory, then run `python assemble.py` and `python write_fma_report.py` from the workspace root. `postprocess.py` converts C designated initializers, lifts tables to device globals, adapts 128-bit arithmetic, and pins NaN behavior. Re-run the sweeps after regeneration.

## cbrt: CORE-MATH's correctly rounded binary64 cube root

The wind-farm power diagnostic (`woof/core/windfarm_power_diag.py`) and the energy products' density correction (`woof.energy.power_farm` and `woof.energy.ramps`, `density_corrected_speed`) take a cube root that must be the same word on the device and on every host. glibc's `cbrt` (LGPL, not transcribed) is not correctly rounded: on glibc 2.44 it differs from the correctly rounded root on 9,185,950 of the 16,777,216 exactly graded arguments below. `pow(x, 1/3)` is not a cube root either. So both roads take CORE-MATH's `cr_cbrt`:

- the upstream source, `upstream/cbrt.c`, kept verbatim. Its revision is `8ae55cdd0d953dc1d6f78659435283d3436865ab` and its sha256 is `0a86b7a8f433dfa4610023767102ea19eb3642ea6982871c61c956148837dde4`, also in `upstream-sha256.json`. It is MIT, "Copyright (c) 2021-2022 Alexei Sibidanov.";
- `woof/core/kernels/cr_cbrt_flt64.cuh`, the device transcription (`uw_cbrt`). It rounds to nearest only, and every operation is an explicit `__d*_rn`/`__fma_rn` intrinsic;
- `woof/core/cr_cbrt.py`, the NumPy transcription. Upstream's `fma(a, b, -fl(ab))` becomes Dekker's exact product error. A subnormal argument is scaled by 2^54 in and 2^-18 out, both exact;
- `woof.core.correctly_rounded_libm.cbrt_cr`, an exact integer reference that shares no code with the three above. It takes the integer cube root of `M 2^(E+3t)` and makes the 53-bit rounding decision by an integer comparison with the midpoint's cube.

`sweep_cbrt.py` grades all four over 2^28 deterministic arguments (16 chunks of 2^24, eight interleaved streams):

- random binary64 bit patterns;
- the diagnostic's density-ratio and rotor-cube ranges;
- log-uniform normals of both signs;
- subnormals;
- exact cubes scaled by powers of eight, and their ±4-word neighbourhoods;
- 1024-word runs across [1, 8);
- upstream's hard-case arguments and their neighbourhoods.

The three fast implementations are compared on every argument. The exact reference grades a 2^20 stride of each chunk.

```bash
gcc -O2 -ffp-contract=off -fopenmp -shared -fPIC \
    tools/uwpbl_wrf471_oracle/libm64/cbrt_batch.c \
    tools/uwpbl_wrf471_oracle/libm64/upstream/cbrt.c -o /tmp/cbrt_batch.so
python tools/uwpbl_wrf471_oracle/libm64/sweep_cbrt.py \
    --library /tmp/cbrt_batch.so --chunks 16 \
    > tools/uwpbl_wrf471_oracle/libm64/gpu-cbrt.log
```
