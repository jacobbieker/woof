# Deng shallow cumulus (shcu_physics = 5) oracle, WRF v4.7.1

The numerical authority for `woof/core/kernels/shcu_deng.cu`: the
byte-unmodified `phys/module_shcu_deng.F` called through the byte-unmodified
`phys/module_shallowcu_driver.F` of WRF v4.7.1 (commit f52c197ed), compiled
with gfortran at `-O0 -ffp-contract=off`.

## Recipe

    python tools/shcu_deng_wrf471_oracle/deng_columns.py write IN.bin --meta IN.json
    pixi exec -s gfortran bash tools/shcu_deng_wrf471_oracle/build.sh WRF-4.7.1 BUILD IN.bin
    GPUWM_NUMERICS=strict python tools/shcu_deng_wrf471_oracle/compare_woof.py IN.bin BUILD/IN-O0.out
    pixi exec -s gfortran bash tools/shcu_deng_wrf471_oracle/coverage.sh WRF-4.7.1 BUILD IN.bin

`build.sh` pins every WRF source by SHA-256 and builds two executables from
them: `O0` (the reference) and `snan` (every local REAL a signalling NaN,
every local INTEGER -2147483647 at entry).  Byte-identical output from the two
means no output word depends on memory the Fortran never wrote.

## What is compiled

| file | role |
|---|---|
| `phys/module_shcu_deng.F` | the scheme, unmodified |
| `phys/module_shallowcu_driver.F` | the driver, unmodified: the TKE source by `bl_pbl_physics` and the closing `RAINSHV = PRATESH*DT` are graded too |
| `phys/module_shcu_grims.F`, `phys/module_shcu_nscv.F`, `share/module_model_constants.F` | unmodified, compiled because the driver USEs them |
| `camuw_stub.F` | generated by `gen_camuw_stub.py`: the real `camuwshcu_driver` dummy-argument declarations sliced out of `phys/module_shcu_camuwshcu_driver.F`, no body (the CAM support chain is not needed for shcu_physics = 5) |
| `stub_wrf.F90` | `module_wrf_error`, `module_dm`, `module_domain`, the `module_state_description` package constants, and the frame externals (`wrf_message`, `wrf_debug`, `wrf_error_fatal`, `get_wrf_debug_level` = 0, `wrf_dm_on_monitor`) |
| `libm_shim.cpp` | the oracle's float32 libm: `expf`, `logf`, `powf` from WOOF's own glibc 2.39 transcription (`woof/core/kernels/glibc_flt32.cuh`), linked ahead of the host library; `sinf` (reachable only from deng's GAMMA at a non-positive argument, which the scheme never forms) aborts |
| `run_deng_oracle.F90` | the column-tile driver: one `shallowcu_driver` call per step, keyword for keyword as `module_first_rk_step_part1.F:1570-1663` makes it, the Deng state carried in the program between steps as the WRF grid carries it |

The libm pin makes the oracle's words independent of the build host (the
receipts were made on macOS arm64, whose libsystem_m is not glibc): the
oracle and the device kernel call the same expf/logf/powf source, so the
gate grades the scheme's arithmetic.  `build.sh` refuses a build whose WRF
objects call any float32 transcendental the shim does not define, and checks
that the executable defines them.

gfortran on arm64 lowers MAX/MIN of REALs to `fmaxnm`/`fminnm` (measured:
`MAX(0.0,-0.0) = +0`, `MIN = -0`, a NaN operand ignored); the kernel uses
`fmaxf`/`fminf`, which behave the same.

## Unreached Fortran

`coverage.sh` lists the executable lines of `module_shcu_deng.F` the fixture
never executes (`tests/data/oracles/shcu_deng/coverage-never-executed.txt`).
Besides the debug prints, the `if_avg_pbl`/`if_avg_tke` = 1 averages (both
hard-wired 0) and the unused lookup-table/TPMIX2/ENVIRTHT2 code, they are:

* `UMF(NK)=VMFPBLCL` (:1572): unreachable, the enclosing test `NK .LE. K`
  always holds inside `DO NK=1,K`.
* the `DMFMIN` downdraft rescale (:2565-2603): unreachable after
  `AINC = MIN(AINCMX, AINC)`, because AINCMX bounds `(UER-DER)(LFS)*AINC` by
  `EMS(LFS)/TIMEC` for every LFS in `LLC..LMAX`, and LFS always is.
* rare arms not reached by these soundings: a saturated post-convective
  mixed layer (:2343-2352), `KFLAG=4` from the `ABEG = 0` and `NCOUNT > 10`
  exits with a >= 4 km cloud (:2427, :2477), the moisture-borrowing zero
  neighbour cases (:2258-2266), `EFFQ = 1` at `TTEMP = TBFRZ` (:1152), a cloud
  top above the model top (:1376), `DMFLFS > 0` (:1967), `LDB = LFS`
  (:1843), the CTEI saturation removal (:3294).
* the places WRF stops (`STOP 907`, `901-904`, the ice-settling guard) or
  reads memory it never wrote (the `ISTOP` mass-imbalance exit before TG is
  formed): the kernel flags these with a status bit and the host refuses the
  step (`woof/core/shcu_deng.py` `STATUS_BITS`).  No fixture column reaches
  any of them.
